# Facilitator Guide: Module 04 — SQL Without Fear

## Overview

The goal of this module is to make data querying feel accessible to participants who have never written a line of SQL. By the end, they should be able to translate a business question into a working SQL query using Copilot — without needing to understand every detail of the syntax.

## Pre-Session Checklist

- [ ] Test DB Fiddle at dbfiddle.uk — confirm SQLite is available
- [ ] Paste and run `saas-business.sql` yourself to verify all inserts work
- [ ] Pre-write the 3 demo queries so you can show expected output
- [ ] Confirm all participants have github.com/copilot access
- [ ] Print or share `lab/questions.md` so participants can work at their own pace

## Session Timing (120 minutes)

| Time | Activity | Notes |
|------|----------|-------|
| 0–15 min | What is a database? Tables, rows, keys | Use the spreadsheet analogy throughout |
| 15–30 min | Demo: SELECT, WHERE, ORDER BY | Run live in DB Fiddle |
| 30–45 min | Demo: GROUP BY, COUNT, SUM | Show the customer-by-plan query |
| 45–60 min | Demo: JOINs explained visually | Draw the Venn diagram on whiteboard |
| 60–100 min | Lab: 10 business questions | Circulate; help with DB Fiddle setup |
| 100–115 min | Debug a broken query together | Pre-break one query to demo error handling |
| 115–120 min | Debrief, safety reminder, Q&A | Always end with the production safety reminder |

## Live Demo Script

### Demo 1: Your First SQL Query
**Setup:** DB Fiddle open with saas-business.sql loaded in schema panel.

**Say:** "Before we use Copilot, let me show you what SQL actually looks like. It reads almost like English."

**Type in query panel:**
```sql
SELECT name, plan, mrr
FROM customers
WHERE plan = 'enterprise'
ORDER BY mrr DESC;
```

**Say:** "Read this out loud with me: SELECT these columns FROM this table WHERE the plan is enterprise. It really is that structured."

### Demo 2: Copilot Translates Plain English
**Say:** "Now I'll ask the same thing using plain English in Copilot. Watch what happens."

**Prompt Copilot:**
> "Write SQLite SQL to find all enterprise customers in the customers table sorted by MRR from highest to lowest. Show: name, plan, mrr."

**Compare the output** to what you hand-wrote. They should be nearly identical.

## Common Questions & Answers

**Q: Do I need to memorize SQL syntax?**
A: No. That's the point of this module. You describe what you want, Copilot writes the SQL. Over time you'll recognize patterns, but memorization is never required.

**Q: What's the difference between SQL and Excel?**
A: Excel works on one file at a time. SQL works on databases with millions of rows across multiple connected tables. The logic is similar — filtering, sorting, summarizing — but SQL scales to enterprise data sizes.

**Q: Is it safe to run these queries on our real database?**
A: Read-only queries (SELECT only) are generally safe but should still be reviewed by a developer before running on production. Never run INSERT, UPDATE, or DELETE generated by AI without expert review.

**Q: What if the query is wrong?**
A: Paste the error message and query back to Copilot with "What is wrong and how do I fix it?" Copilot is excellent at debugging its own output.

**Q: Can I use this in Snowflake/BigQuery/Redshift instead of SQLite?**
A: Yes. Tell Copilot which database you're targeting and it will adjust the syntax. Most SELECT/JOIN/GROUP BY syntax is the same.

## Troubleshooting

| Problem | Likely Cause | Fix |
|---------|-------------|-----|
| DB Fiddle won't load | Browser issue | Try Chrome incognito or a different browser |
| Schema inserts fail | Wrong database selected | Make sure SQLite is selected, not MySQL |
| Query returns no rows | WHERE clause too strict | Ask Copilot: "Why does this query return 0 rows?" |
| "no such table" error | Schema wasn't loaded | Re-run the schema SQL in the left panel first |

## Energy Management Tips

- Do Question 1 as a whole group before releasing to independent work
- Pair participants — one types the Copilot prompt, the other reviews the output
- When someone gets a working query, ask them to read their prompt aloud — peer learning is powerful
- The debugging demo at minute 100 is high-energy — use it to re-engage a tired room
